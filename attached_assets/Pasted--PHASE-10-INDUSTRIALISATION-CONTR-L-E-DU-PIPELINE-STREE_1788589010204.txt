# PHASE 10 — INDUSTRIALISATION CONTRÔLÉE DU PIPELINE STREET VIEW 3D

## CONTEXTE

Les phases précédentes ont permis de :

* auditer l'ancien module Street View ;
* réactiver le parcours de contribution ;
* préparer le stockage et les métadonnées ;
* préparer l'architecture asynchrone ;
* définir l'architecture 3D cible ;
* préparer un environnement expérimental ;
* tester le pipeline de reconstruction ;
* expérimenter COLMAP / SfM / MVS / 3D Gaussian Splatting.

La Phase 9 devait permettre de déterminer si une vidéo peut réellement produire une représentation 3D exploitable.

Cette phase commence UNIQUEMENT à partir des résultats réels de :

`experiments/streetview-3d/PHASE_9_RESULT.md`

---

# OBJECTIF

Transformer le prototype validé en une architecture capable de traiter progressivement les futures contributions utilisateurs.

↓

PUBLICATION FUTURE

IMPORTANT :

Cette phase ne doit PAS encore créer l'explorateur 3D public.

Elle doit construire le moteur de traitement fiable qui permettra de le faire ensuite.

# ÉTAPE 3 — ARCHITECTURE DES WORKERS

Concevoir une séparation claire :

## API

Responsable de :

* authentification ;
* contribution ;
* upload ;
* métadonnées ;
* création des jobs ;
* consultation du statut ;
* administration.

L'API NE DOIT PAS effectuer de reconstruction 3D lourde.

---

## CPU WORKER

Responsable de :

* récupération du job ;
* téléchargement/lecture de l'original ;
* validation ;
* extraction vidéo ;
* extraction des métadonnées ;
* sampling des frames ;
* prétraitement ;
* préparation COLMAP ;
* SfM ;
* MVS si approprié ;
* génération des artefacts intermédiaires ;
* transmission vers le GPU worker.

---

## GPU WORKER

Responsable de :

* réception d'un dataset validé ;
* entraînement/reconstruction 3DGS ;
* génération des artefacts 3D ;
* validation minimale ;
* stockage du résultat ;
* retour du statut.

---

# ÉTAPE 5 — JOBS ATOMICQUES

Chaque étape doit être un job identifiable.

Exemples :

`VIDEO_VALIDATE`

`FRAME_EXTRACTION`

`SFM_RECONSTRUCTION`

`MVS_RECONSTRUCTION`

`GAUSSIAN_SPLATTING`

`QUALITY_CHECK`

Chaque job doit avoir :

* id ;
* contributionId ;
* type ;
* status ;
* attempts ;
* maxAttempts ;
* progress ;
* priority éventuelle ;
* workerId ;
* startedAt ;
* completedAt ;
* createdAt ;
* updatedAt ;
* errorCode ;
* errorMessage ;
* inputArtifact ;
* outputArtifact.

---

# ÉTAPE 6 — IDempotence

Un job ne doit jamais produire deux fois des artefacts incohérents simplement parce qu'un worker a redémarré.

Implémenter des protections contre :

* double exécution ;
* timeout ;
* crash ;
* restart ;
* réseau interrompu ;
* worker mort ;
* job déjà terminé.

Avant chaque étape :

vérifier l'état actuel.

Exemple :

si `SFM_COMPLETED` existe déjà,

ne pas relancer inutilement SfM.

---

# ÉTAPE 7 — RETRY

Mettre en place :

* nombre maximum de tentatives ;
* backoff ;
* distinction erreur temporaire / permanente ;
* journalisation ;
* état final FAILED.

Exemples temporaires :

* GPU indisponible ;
* timeout réseau ;
* stockage temporairement inaccessible.

Exemples permanents :

* vidéo corrompue ;
* vidéo trop courte ;
* qualité insuffisante ;
* absence de données exploitables ;
* reconstruction impossible.

---

# ÉTAPE 8 — STOCKAGE DES ARTEFACTS

Structurer proprement les fichiers.

Exemple :

`streetview/{contributionId}/original/`

`streetview/{contributionId}/frames/`

`streetview/{contributionId}/sfm/`

`streetview/{contributionId}/mvs/`

`streetview/{contributionId}/3dgs/`

`streetview/{contributionId}/preview/`

`streetview/{contributionId}/logs/`

La base de données ne doit PAS contenir les fichiers lourds.

Elle contient uniquement :

* références ;
* métadonnées ;
* statuts ;
* métriques ;
* relations.

---

# ÉTAPE 9 — NETTOYAGE

Définir une politique de rétention.

Exemple :

Original :
CONSERVÉ.

Résultat 3D :
CONSERVÉ.

Preview :
CONSERVÉ.

Frames :
TEMPORAIRE ou conservés selon politique.

Artefacts MVS :
TEMPORAIRES.

Logs détaillés :
RÉTENTION LIMITÉE.

Ne supprimer aucun artefact nécessaire à une reconstruction ou à une future vérification sans règle explicite.

---

# ÉTAPE 10 — GPU WORKER TEMPORAIRE

Le GPU ne doit PAS devenir une machine allumée en permanence sans nécessité.

Étudier une architecture permettant :

* démarrage à la demande ;
* traitement d'un lot ;
* arrêt après inactivité ;
* limitation de concurrence ;
* contrôle du coût.

Documenter :

* coût par heure ;
* coût par reconstruction ;
* temps moyen ;
* capacité GPU ;
* nombre de jobs simultanés.

Ne pas activer automatiquement un fournisseur cloud payant sans validation humaine.

---

# ÉTAPE 11 — CONCURRENCE

Définir :

* nombre de jobs CPU simultanés ;
* nombre de jobs GPU simultanés ;
* verrouillage ;
* réservation d'un job ;
* heartbeat worker ;
* timeout ;
* récupération des jobs abandonnés.

Le système doit empêcher :

Worker A → job 123

et simultanément :

Worker B → job 123.

---

# ÉTAPE 12 — OBSERVABILITÉ

Chaque reconstruction doit être traçable.

Conserver :

* contribution ;
* job ;
* worker ;
* durée ;
* étape ;
* statut ;
* taille input ;
* taille output ;
* erreurs ;
* consommation estimée ;
* timestamps.

Créer des logs structurés.

NE JAMAIS enregistrer :

* tokens ;
* mots de passe ;
* secrets ;
* clés privées ;
* credentials ;
* URLs signées complètes si elles contiennent des informations sensibles.

---

# ÉTAPE 13 — QUALITÉ

Avant qu'une scène soit considérée comme publiable :

vérifier automatiquement autant que raisonnablement possible :

* nombre de frames ;
* images alignées ;
* qualité SfM ;
* nombre de points ;
* couverture ;
* éventuels trous ;
* taille du résultat ;
* présence des artefacts attendus ;
* intégrité du résultat 3DGS.

Créer un statut :

`QUALITY_PASS`

ou

`QUALITY_REVIEW`

ou

`QUALITY_FAIL`

Ne jamais publier automatiquement une scène manifestement mauvaise.

---

# ÉTAPE 14 — MÉTADONNÉES GÉOSPATIALES

Conserver dès maintenant les données nécessaires au futur géoréférencement :

* latitude ;
* longitude ;
* altitude si disponible ;
* précision GPS ;
* orientation ;
* timestamp ;
* appareil ;
* trajectoire éventuelle.

IMPORTANT :

Ne PAS prétendre que ces coordonnées constituent déjà le géoréférencement précis de la reconstruction.

À ce stade :

GPS = information de localisation.

La géométrie reconstruite doit encore être alignée correctement dans le système géospatial futur.

---

# ÉTAPE 15 — DIMENSION TEMPORELLE

Préparer dès maintenant la possibilité d'avoir plusieurs captures du même endroit :

Exemple :

Rue X
→ capture 2026
→ capture 2027
→ capture 2028

Ne pas écraser l'ancienne scène.

Chaque reconstruction doit être versionnée.

Prévoir conceptuellement :

`LOCATION`

→ plusieurs

`SCENE_3D`

avec :

* capturedAt ;
* processedAt ;
* version ;
* sourceContributionId ;
* status.

# CRITÈRE DE RÉUSSITE

La Phase 10 est réussie si :

1. une contribution peut traverser le pipeline complet ;
2. chaque étape est traçable ;
3. un worker peut redémarrer sans casser le job ;
4. les jobs sont idempotents ;
5. les fichiers lourds restent dans le stockage approprié ;
6. le GPU reste séparé de l'API ;
7. les erreurs sont récupérables ;
8. les scènes sont versionnables ;
9. les données géographiques sont conservées ;
10. aucun résultat fictif n'est généré ;
11. aucune modification dangereuse de production n'est introduite.

---
