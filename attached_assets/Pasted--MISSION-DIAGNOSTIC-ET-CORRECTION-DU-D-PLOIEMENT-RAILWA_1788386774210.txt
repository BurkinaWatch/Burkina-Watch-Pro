# ÉTAPE 5 — SÉCURITÉ DES SECRETS

Le Dockerfile généré par Railway contient actuellement des constructions du type :

```dockerfile
ARG CLIENT_SECRET
ARG GROQ_API_KEY
ARG SESSION_SECRET
...
```

puis :

```dockerfile
ENV CLIENT_SECRET=$CLIENT_SECRET
ENV GROQ_API_KEY=$GROQ_API_KEY
ENV SESSION_SECRET=$SESSION_SECRET
...
```

Corrige cette architecture.

Les secrets privés doivent être fournis par les variables d'environnement Railway et consommés par l'application au runtime.

Ne mets jamais de valeur secrète directement dans :

* le code source ;
* `Dockerfile` ;
* `ARG` ;
* des fichiers committés ;
* des logs ;
* le frontend.

Attention également à :

```text
VITE_GOOGLE_MAPS_API_KEY
```

Une variable préfixée `VITE_` est destinée au bundle frontend et ne doit donc jamais être considérée comme un secret backend. Vérifie son usage et distingue clairement :

* variables publiques nécessaires au frontend ;
* secrets strictement backend.

Ne casse aucune fonctionnalité existante liée à Google Maps.
