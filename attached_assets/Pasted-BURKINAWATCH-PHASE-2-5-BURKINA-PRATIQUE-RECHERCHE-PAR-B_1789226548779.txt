BURKINAWATCH — PHASE 2/5
BURKINA PRATIQUE — RECHERCHE PAR BESOIN

À partir de l'audit validé, implémente uniquement cette phase.

==================================================
RÈGLE DE SÉCURITÉ DU PROJET
==================================================

La fonctionnalité actuelle est conservée.

Ne supprimer :
- aucune catégorie ;
- aucun lieu ;
- aucune route ;
- aucune fiche ;
- aucune carte ;
- aucun filtre existant.

Ne créer aucune deuxième base de lieux.

Ne modifier aucune configuration Railway.

Ne modifier aucun secret ou variable d'environnement.

Ne modifier les commandes build/start que si une nécessité absolue est démontrée.
Dans ce cas, STOP et demande validation.

==================================================

Supporter notamment :

"je cherche une pharmacie ouverte"

"je veux retirer de l'argent"

"où manger pour 3000 F"

"je cherche un mécanicien"

"ma voiture est en panne"

"je cherche un plombier"

"mon téléphone est cassé"

"où acheter du ciment"

"je cherche une chambre"

"je cherche une station"

"où trouver un marché"

"je cherche un service administratif"

==================================================
FILTRES
==================================================

Comprendre lorsque possible :

- ouvert maintenant ;
- de garde ;
- proche ;
- budget en FCFA ;
- disponible ;
- aujourd'hui ;
- date ;
- besoin urgent.

Ne jamais inventer une information absente.

==================================================
RÉSULTAT
==================================================

Les résultats doivent progressivement pouvoir distinguer :

📍 LIEU
🎁 OFFRE
👁️ SIGNAL

Exemple :

Utilisateur :
"où manger pour moins de 3000 F ce soir ?"

Résultat possible :

LIEU
Restaurant X

OFFRE
Menu à 2500 F

SIGNAL
Confirmé ouvert récemment

==================================================
CATÉGORIES EXISTANTES
==================================================

Un utilisateur qui tape simplement :

"restaurants"

doit continuer à accéder à l'expérience actuelle des restaurants.

Un utilisateur qui tape :

"restaurant ouvert ce soir à moins de 3000"

doit pouvoir bénéficier de la nouvelle logique.

Les deux usages doivent coexister.
