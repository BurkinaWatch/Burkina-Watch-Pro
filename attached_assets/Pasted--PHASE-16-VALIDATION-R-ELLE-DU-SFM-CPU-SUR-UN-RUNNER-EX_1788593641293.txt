# PHASE 16 — VALIDATION RÉELLE DU SFM CPU SUR UN RUNNER EXTERNE ISOLÉ

## CONTEXTE

Nous avons terminé la Phase 15.

Le verdict de la Phase 15 est :

```text
NO-GO dans l'environnement CPU actuel
```

Ce verdict ne signifie PAS que COLMAP/SfM CPU est techniquement impossible.

La cause exacte du blocage est :

```text
COLMAP absent du runner Replit
```

L'environnement Replit actuel dispose notamment de :

* Linux x86_64
* 4 vCPU
* environ 7.8 GiB RAM
* aucun GPU NVIDIA
* FFmpeg 6.1.2
* FFprobe 6.1.2
* Docker 27.5.1
* aucun binaire COLMAP
* installation Nix COLMAP précédemment bloquée par une dépendance FreeImage vulnérable

Aucun contournement de sécurité ne doit être utilisé.

Nous voulons maintenant répondre à une question très précise :

```text
Peut-on exécuter une première reconstruction SfM réelle de notre dataset
synthétique sur CPU dans un environnement externe, isolé et reproductible ?
```

IMPORTANT :

Cette phase est une EXPÉRIENCE DE LABORATOIRE.

Elle ne doit PAS modifier ou connecter la production BurkinaWatch.

# 14. VALIDATION DU MODÈLE

Un simple code retour `0` ne suffit pas.

Vérifier que le modèle sparse est réellement exploitable.

Contrôler :

* existence des fichiers du modèle ;
* cohérence cameras/images/points3D ;
* nombre réel d'images enregistrées ;
* présence de points 3D ;
* observations cohérentes ;
* erreur de reprojection raisonnable ;
* absence de fichiers vides ou corrompus.

Si possible, utiliser les outils COLMAP pour inspecter le modèle.

Ne pas fabriquer de visualisation si aucun modèle réel n'existe.
