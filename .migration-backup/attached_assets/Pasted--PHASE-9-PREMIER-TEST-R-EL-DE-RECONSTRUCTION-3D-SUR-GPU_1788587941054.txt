# OBJECTIF DE CETTE PHASE

L'objectif est maintenant de réaliser le **premier test technique réel de reconstruction 3D**, dans un environnement GPU temporaire et totalement séparé de BurkinaWatch production.

Le pipeline expérimental cible est :

VIDEO
→ extraction des frames
→ prétraitement
→ COLMAP / SfM
→ estimation des poses caméra
→ reconstruction sparse
→ MVS / dense reconstruction si possible
→ préparation des données
→ 3D Gaussian Splatting
→ génération d'un véritable résultat 3D
→ inspection/validation du résultat

Cette phase doit permettre de répondre à une question simple :

> **Sommes-nous techniquement capables de transformer une vidéo en une représentation 3D exploitable avec notre architecture cible ?**

# ÉTAPE 2 — DÉFINIR L'ENVIRONNEMENT GPU

Avant de lancer COLMAP ou 3DGS, définir précisément les besoins matériels.

Comparer au minimum :

1. GPU NVIDIA avec environ 16 GB VRAM ;
2. GPU NVIDIA avec environ 24 GB VRAM ;
3. GPU NVIDIA avec davantage de VRAM si nécessaire.

Évaluer :

* type de GPU ;
* VRAM ;
* CUDA ;
* durée de démarrage ;
* coût horaire estimatif ;
* stockage temporaire ;
* accès SSH ou équivalent ;
* possibilité d'utiliser Docker ;
* compatibilité COLMAP ;
* compatibilité 3DGS ;
* possibilité d'installer les dépendances ;
* possibilité de détruire complètement l'environnement après expérimentation.

Ne pas choisir un fournisseur uniquement parce qu'il est connu.

Choisir l'environnement qui présente le meilleur compromis :

**compatibilité + simplicité + coût + reproductibilité.**

Si plusieurs solutions sont possibles, présenter le comparatif avant de lancer une instance coûteuse.

---

# ÉTAPE 9 — CRITÈRES DE VALIDATION SfM

Déterminer objectivement si le SfM est exploitable.

Documenter :

* taux d'images enregistrées ;
* stabilité des poses ;
* cohérence de la trajectoire caméra ;
* densité du nuage sparse ;
* éventuelles dérives ;
* éventuels problèmes de calibration ;
* éventuels trous ou ruptures.

Classer le résultat :

### PASS

SfM suffisamment cohérent pour continuer.

### PASS WITH WARNINGS

Résultat exploitable mais avec problèmes à documenter.

### FAIL

Résultat insuffisant pour poursuivre vers une reconstruction fiable.

Si FAIL :

**arrêter ici et analyser la cause.**

Ne pas masquer l'échec.

---

Mais :

**NE PAS intégrer ce viewer dans BurkinaWatch.**

# RÈGLE DE TRANSPARENCE

Ne jamais écrire qu'une reconstruction a réussi si :

* seul le fichier existe ;
* seule une commande s'est terminée ;
* un viewer affiche quelque chose sans véritable reconstruction ;
* une scène artificielle a été générée ;
* la vidéo a simplement été transformée en frames ;
* un résultat 3D a été simulé.

Une réussite doit correspondre à un véritable résultat issu du pipeline de reconstruction.
