# BURKINAWATCH — PHASE 1.2

## Validation finale de la production Railway

Tu travailles sur le projet **BurkinaWatch**.

Cette phase est une phase de **validation opérationnelle ciblée** après le rapport de Phase 1.1.

L'objectif unique est de déterminer si la production Railway est réellement opérationnelle.

---

## ⚠️ RÈGLES ABSOLUES

Cette phase est strictement limitée à la validation de la production Railway.

### INTERDICTIONS

Ne fais aucune modification de code source.

Ne modifie aucun fichier applicatif.

Ne modifie pas :

* `client/`
* `server/`
* `shared/`
* `migrations/`
* `package.json`
* `package-lock.json`
* `vite.config.ts`
* `drizzle.config.ts`

Ne crée aucune migration.

Ne lance pas :

```bash
npm run db:push
```

Ne lance pas :

```bash
drizzle-kit migrate
```

Ne crée pas :

```text
__drizzle_migrations
```

Ne modifie aucune table PostgreSQL.

Ne modifie aucune donnée PostgreSQL.

Ne supprime aucune donnée.

Ne fais aucun changement de schéma.

Ne commence PAS Expo.

Ne commence PAS React Native.

Ne commence PAS EAS.

Ne commence PAS l'OTA.

Ne refactorise PAS le Web.

Ne modifie PAS l'interface utilisateur.

Ne modifie PAS l'authentification dans le code.

Ne change PAS la chaîne de build.

Ne génère aucune nouvelle architecture.

# 4. VALIDATION DE REFRESH_TOKEN_SALT

Le précédent audit a montré que le démarrage production local échouait avec :

```text
REFRESH_TOKEN_SALT doit être défini en production avec une valeur stable.
```

Vérifie maintenant directement dans Railway Production :

```text
REFRESH_TOKEN_SALT
```

### Si elle est présente

Ne la modifie surtout pas.

### Si elle est absente

Si tu as réellement la possibilité de modifier les variables Railway :

* crée une valeur cryptographiquement aléatoire ;
* mets-la directement dans Railway ;
* ne l'affiche jamais ;
* ne l'écris jamais dans un fichier ;
* ne la commite jamais ;
* ne la transmets jamais dans le rapport.

Si tu n'as pas l'autorisation ou la capacité technique de modifier Railway :

```text
ACTION MANUELLE REQUISE
```

et arrête-toi.

Ne contourne jamais cette exigence dans le code.

---

# 5. VALIDATION KMS / CHIFFREMENT

Lis la valeur de :

```text
KMS_ENABLED
```

sans révéler de secret.

### Si KMS_ENABLED=false

Vérifie que :

```text
MASTER_ENCRYPTION_KEY
```

est présente.

### Si KMS_ENABLED=true

Vérifie que les quatre paramètres suivants sont présents :

```text
KMS_PROJECT_ID
KMS_LOCATION_ID
KMS_KEY_RING_ID
KMS_CRYPTO_KEY_ID
```

Ne modifie pas la configuration KMS dans cette phase.

Si la configuration est incomplète :

```text
KMS CONFIGURATION = INCOMPLETE
```

et explique exactement quelle variable manque, sans révéler de valeur.

---

# 9. VALIDATION DU DÉMARRAGE

Après le déploiement, consulte les logs Railway.

Nous voulons confirmer que :

```text
dist/index.js
```

démarre correctement.

Vérifie particulièrement l'absence de :

```text
REFRESH_TOKEN_SALT
DATABASE_URL
RAILWAY_DATABASE_URL
SESSION_SECRET
KMS
PostgreSQL
connection refused
authentication error
S3
StreetView
crash
restart loop
```

Le processus doit atteindre :

```text
server.listen()
```

ou son équivalent fonctionnel.

Puis rester actif.

Résultat attendu :

```text
PROCESS = STABLE
```
